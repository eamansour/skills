## Step 1: Identify All Outdated Dependencies and Latest Versions

Run the following command in the directory containing `package.json` to list all outdated dependencies:

```bash
npm outdated
```

The output is a table with columns: `Package`, `Current`, `Wanted`, `Latest`, `Location`, `Depended by`.

| Column | Meaning |
|--------|---------|
| `Current` | The version currently installed |
| `Wanted` | The highest version satisfying the declared range in `package.json` |
| `Latest` | The latest published version on the npm registry |

Classify each outdated package against its `Current` version using the `Latest` column.

If `npm outdated` produces no output, all direct dependencies are already at their latest versions — no updates are required.

## Step 2: Apply Dependency Version Updates

For each dependency that has a newer version available, run the following command in the directory containing `package.json`:

```bash
npm install <package-name>@<new-version>
```

This updates the version in `package.json` and regenerates `package-lock.json` to reflect the new resolved dependency graph.

After applying an update, verify using the following order of preference:

1. **If `build.sh` (or equivalent) exists and can be run** (all external prerequisites are available): use it — this is the authoritative build. Follow the general SKILL.md rule; do not substitute raw commands.
2. **If `build.sh` cannot be run** (e.g. requires unavailable network resources, missing system tools): use raw commands from inside the `package.json` directory:
   ```bash
   npm clean-install
   npm test -- --watchAll=false
   npm run build
   ```
   If you fall back to this lighter path, you must have received explicit user confirmation first (see the Environment prerequisite failures rule in SKILL.md).

After applying an update, verify `package-lock.json` was regenerated by confirming its `lockfileVersion` block and the updated package entry reflect the new version. If `package-lock.json` is absent or stale, run:

```bash
npm ci
```

to regenerate it from the current `package.json`.

Use the general SKILL.md guidance for patch, minor, and major update strategy and result classification.
